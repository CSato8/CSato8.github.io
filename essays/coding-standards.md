*A Land of Red Squiggly Lines*

## The Red Line of Doom And Despair
I either hate it or am mildly frustrated with it. Here I am, enjoying my peaceful life coding when a giant red line with red highlights crash lands on top of my text. Naturally, the line of code I had just written becomes two times harder to read and this mild annoyance forces me to correct whatever error I have bestowed upon my file. Of course, these errors are usually extremely easy to fix that take maybe five seconds (or ten if you really don't know what the error is telling you) of your oh so precious time.

## The ESLint Experience
Most of the syntax errors ESLint throws at me are ones that I would have never known unless I installed the plugin for VSCode. The two big offenders for me are the two spaces for indents and single quotes rather than double. Through the very few years that I have spent coding I have built up the muscle memory of pressing tab for indenting lines. I would like to believe that I am not wrong in believing that it is the most convenient key to have, the latter being to press space several times. However, all of the muscle memory is now tested against the brick wall that is "line level 4 expected 2". In just the one week I have used ESLint I could not tell you the amount of times I pressed tab just to then miserably move my cursor back to remove the indention.

## Is It Useful?
As much of an annoyance as these coding standard errors are, I can't deny that they are helpful. However, they are not just helpful for typing code that is cleaner and easier to read, but also learning somethings about the language itself. Lets start with the obvious: coding standards help with keeping code easy to understand. It is not a stretch to say that coding standards benefits everyone. Not only is it easy for you as the creator to manage the code in the long run, but it also allows for others to work on the program and understand it. But, I can also agree that coding standards is a somewhat powerful way to learn a programming language. Although I have only worked with ESLint for a week and have not truly experienced it enough to learn anything yet, I understand its use in writing correct syntax. When it comes to learning a new programming language, I feel that most of the battle comes with learning the correct syntax. Once you understand how to structure code it is pretty simple to translate it into any language, the only barrier is syntax. Coding standards help with ensuring that the syntax you wrote is correct by hurling errors until you learn.
